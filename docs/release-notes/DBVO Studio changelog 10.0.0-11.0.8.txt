Version 11.0.8 (everything since 10.0.0)
- New: Proofread lines in Phase 1. Proofread… goes through the lines one at a time so you can fix spelling and grammar, with the spellchecker (right-click for suggestions) and optional AI suggestions from your AI provider, 50 lines per request ahead of where you are. Each suggestion shows what changes and why; style-only changes are marked "check before accepting". Game markup such as <Alias=Player> and (Persuade) is locked and never sent to the AI. Suggestions stay inside the DBVO script's rules (no semicolons, brackets, curly quotes, leading "..." or mid-line parentheses), text you type is checked as you go, and Save & next goes straight to the next line with something to fix. Saved edits go into the DBVO Fix plugin, and a summary shows what you changed.
- AI Auto Tag (Phase 2): accept or undo all suggestions at once with "AI tags (N) ▾" in the status bar, Ticked ▾ for the ticked lines, or Shift-click on a row's ✓ or ✕ for every line shown.
- AI provider: newer Claude models (such as claude-haiku-5-5) work for AI Auto Tag and Proofread lines. They refused every request with "`temperature` is deprecated for this model".
- BSA archives: file and folder names are stored in Windows-1252, the code page Skyrim SE looks them up in. Names with ’ “ ” … – — † ™ • œ and a few others were written as "?" inside the archive, so the game never found those files. A name Windows-1252 can't hold at all now stops the build with the file named. Already-built packs only need the FOMOD built again, no new generation. Since 11.0.6 the FOMOD BSA option also packs those names into the BSA instead of leaving them loose next to it; only names Windows-1252 can't hold stay loose.
- Clicks: right after typing in a list, the next click on a button such as ★, ⚑, ♪ or ⊘ sometimes needed a second click. One is enough now.
- The spinning ↻: clicking regenerate on several lines quickly could leave a ↻ spinning after the take arrived, stop one too early, or lose one of the takes. Each ↻ now follows its own request, also in the queue.
- Changing folders, options or Books part settings while that project generates could drop takes you paid for. Those changes now wait; Books text you edit meanwhile is saved when the generation ends.
- Menus: a long menu (Post-processing > Effects) could open partly above the window. Menus now always open fully on screen, and a long list scrolls.
- DBReV packs (BETA TESTING): reference sets no longer leave lines out, text variants of one line no longer pick up each other's files, and Phase 2 says when kept takes go past DBReV's 20 files per line.
- OpenAI-compatible: your OpenAI key is never sent to a server on your PC or network, a full endpoint address (…/v1/audio/speech) works, and long Books parts get more time.
- Player Grunts' Whisper, NPC Revoice's original audio and .fuz previews no longer ask for FaceFX and FonixData.
- New in Phase 1: an optional mod page field (Nexus, LoversLab or elsewhere) when you create a mod. With the version, it goes into the FOMOD option's description.
- FOMOD option descriptions start as: the mod's name, its number of lines, the DBVO Fix notice when the option installs a fix plugin ("ℹ️ Contains formatting fix ESPFE patch. Let the plugin overwrite the original mod."), then ⭐ and the mod page, and the version.
- Add DBVO Patches: nothing is ticked when the list opens. "Tick new ones" ticks every patch not in the FOMOD yet, one patch per mod; a patch is "already in" when every one of its mods has its option, "partly in" when some do, and "same name in" when an option named like one of its mods is there but not linked (as in an imported FOMOD), so nothing gets a second option by accident. "Untick all" clears the list, a search box narrows it, the Add button counts what's ticked, and "Sort each group A–Z" only sorts the groups it added options to.
- FOMOD builder, moving things: clicking ↑ or ↓ again after a move moved the page, group or option back, and Delete or Duplicate right after a move could hit the wrong one. Each click now acts on where it is now. ⤒ and ⤓ move straight to the top or bottom, and pages and groups can be dragged in the tree (groups onto another page).
- FOMOD builder, new pages anywhere: + Page above and + Page below on a page, the button under the tree adds below the page you have open, and right-click a page for the same plus moving and Delete. Right-click a group for + Group above, + Group below and + Option.
- FOMOD order: the order of the pages and of each page's groups can be set (As listed, A–Z, Z–A). Many imported FOMODs are A–Z, where the installer sorts by name whatever the order in the tree; moving something in such a list takes the order the installer showed and switches it to As listed. Simulate install shows everything in the installer's order.
- FOMOD saves go out in order and are never dropped: Add DBVO Patches, Refresh linked and Build first send the save that's waiting, and while Add DBVO Patches or Refresh linked work the editor waits, so nothing you type is overwritten by their result. A failed save stops them instead of going ahead. Leaving the editor sends a waiting save at once.
- Clear about where your edits go: a note in Installer & info.xml says your edits are saved in DBVO Studio, not in your FOMOD folder, and that Build ▾ writes the installer with your changes (zipping your own FOMOD folder by hand ships the old ModuleConfig.xml).
- Build without packing (was "Stage only") writes the finished installer as a folder right next to its archive, with the same name: <release folder>\<name version>, the folder to zip yourself with 7-Zip if you like (select everything inside it). It's only replaced when it's an installer DBVO Studio built, never a folder of yours. Old _staging folders can be deleted.
- FOMOD build progress: the bar at the top shows at once and says which step it's on (updating linked options, checking, backing up, listing files), then counts the files; it moves while 7-Zip packs instead of sitting at 0.
- Working indicator: anything that takes more than a moment (reading plugins, creating or opening a mod, saving, adding patches) shows a "Working…" chip with a spinner at the top, with the seconds after a while.
- DBVO voice pack JSON: when the installer already installs one itself, as many imported FOMODs do, DBVO Studio adds no second one; the JSON panel shows the file it found and Validate no longer asks for a carrier option. Imports also recognise a JSON installed deeper down (DragonbornVoiceOver\voice_packs\…, DBReV, or with / in the path).
- FOMOD import keeps the header image's showImage, showFade and height, alwaysInstall and installIfUsable written as 1 or 0, text in files declared as windows-1252 and the like, and no longer copies a foreign XML namespace into flags and conditions.
- FOMOD build: two sources outside the FOMOD root with the same name (two "Sound" folders, two preview.png images) each keep their own files, and Refresh linked no longer removes a DBVO Fix plugin of another mod you added to a linked option by hand. Validate warns about a folder with no source (it installs the whole FOMOD root), and Duplicate makes an unlinked copy.
- FOMOD options linked to a DBVO Patch respect your edits: Refresh linked and Build only add DBVO Fix plugins that exist in the patch's folder; a linked file you remove with × stays removed (↺ puts it back); a priority you set on a linked file stays; files you add yourself (another Sound folder, a fix plugin of another mod) are never removed, and the patch's own audio stays next to them; edits made while a build runs are kept. A linked file's source and destination can't be retargeted in the files table, since every refresh rewrites them from the patch.
- FOMOD build: a file, folder or image that isn't on disk is left out of the installer's XML too (and listed in the build report), so no option points at a file the archive doesn't have. Files installed by conditional installs of an imported FOMOD are now copied into the installer; before, the XML listed them but the archive lacked them. A .7z is packed under a temporary name, so a cancelled or failed build leaves the previous archive as it was.
- Re-import… makes a backup first and keeps options linked to their DBVO Patches (matched by name), plus your BSA, archive and encoding settings.
- Simulate install: in a pick-one group, the option you click is the one picked (a pre-ticked one no longer wins), and Required options stay ticked.
- AI tag suggestions (Phase 2 and NPC Revoice) are never attached to a line whose text changed while the AI worked, and adding or removing tags or Reset spoken clears an outdated one, so Accept all can't put back old text.
- Proofread lines: when the AI saw a mistake but its fix would break the line's markup or the script's rules, the line is no longer passed over as fine; it says so, for you to check. A line with a non-breaking space is no longer saved as an edit when you didn't touch it, and a line you edited is asked about again when you go back to it.
- Folders & options (Phase 2) says up front when the patch is generating, instead of throwing away what you filled in.
- A queued job of the same kind shows its progress bar from its first step; background calls (AI proofreading, rule checks) no longer show the Working… chip.
- Lots of smaller bug fixes, among them: saves no longer fail when another part of the app reads the same file, NPC Revoice and Voiced Books scans can be cancelled, lines left "Generating" after closing mid-batch are reset, takes with # or % in their names play, and player-name lines export to your real Downloads folder.
- User guide and PDF: a new section on Proofread lines, what the DBVO Fix plugin copies from a mod (with a note on load order), and DBReV packs with reference sets. Also: the FOMOD builder's new page, group and order tools, the mod page field, and where builds go. New screenshots of the FOMOD builder, and sections on linked options, where builds go and the Working… indicator.
