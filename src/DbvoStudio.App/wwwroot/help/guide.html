Introduction

DBVO Studio takes a Skyrim mod from its plugin to a finished, installable Dragonborn Voice Over (DBVO) voice pack in three phases. Three stand-alone tools sit beside them. The top bar shows the phases in order; Other Tools ▾ opens the tools and ⚙ Global Settings holds everything that applies to the whole app.

Phase 1 decides what is said, Phase 2 decides how it sounds, and Phase 3 decides how it is installed. You can export at any stage and skip the FOMOD altogether.

The guide follows the same order: setup, the three phases, the two tools, a reference of greyed-out buttons, then files and troubleshooting. Every button in the app also has a tooltip. The screenshots use sample data: the base game plugins as the mod, and a voice pack called Sample Voice.

Getting started

After installing, and before your first mod, do four things in ⚙ Global Settings: choose the Library location, check the tools, add your ElevenLabs key, and create a voice pack. Everything there saves as you change it.

1. Install and launch

Unzip the build anywhere and run DBVO Studio.exe. It needs Windows 10 or 11 with the Microsoft Edge WebView2 runtime, which Windows already includes. ffmpeg and 7-Zip ship in the app's Tools folder. A splash screen shows while the studio starts and closes as soon as the first page is ready.

2. Choose the Library location first

The Library holds every project, take and backup. It starts in Documents\DBVO Studio, and moving it later means copying every take, so set it before you start: General & tools → Library → Change….

  • Keep the path short, such as D:\DBVO Studio Library. Windows limits paths to 260 characters and DBVO file names are long.

  • Use the drive your WAV + LIP files are on. On the same drive, a take and its exported copy are hardlinked: one file on disk, no extra space, written instantly. Across drives every file is copied.

  • Change… takes an empty folder (your Library is copied into it) or a folder that already holds a Library (used as it is). The app restarts afterwards.

3. Check the tools

The Tools section shows a ✓ or ✕ badge per tool, and ⓘ explains how to get each one. Empty or broken paths are filled in on every start from the included copies, an installed DBVO Voice Pack Maker, your Skyrim folder and the default Steam folder.

Paste the key under ElevenLabs → API key and click Save key; it is stored encrypted for your Windows user. Test shows your plan and the characters used.

Optional settings

None of these are needed to start; come back to them when you want them.

AI auto-tagging

ElevenLabs has no API for its Enhance button, so AI Auto Tag (Phase 2 and NPC Revoice) asks an AI model to add [tags] without changing any words; suggestions that change words are thrown away. Pick a preset (Ollama or LM Studio, free on your PC; OpenAI or Anthropic, paid), follow its numbered steps, add a key for online providers, then Test connection.

Pronunciation

A global dictionary used by every voice pack. Sounds like respells a word and works with every engine; IPA is exact, but only ElevenLabs v3/v4 and Flash v2 read it. Whole word and Match case narrow the match. Only the spoken text changes, never subtitles or file names. Import and export work with DBVO Voice Pack Maker 2.7.0, CSV and .pls files.

Omit references

Topic .txt files of lines every user already has, such as the base game voice pack. In a patch, lines found in a ticked reference are omitted, so you never voice a line twice. Only add packs every user installs, never optional mods.

Start page

General & tools → Start page decides what you see when DBVO Studio opens: the Landing page (the default) or Where I left off, the page you had open last time. The DBVO Studio logo at the top left always opens the landing page.

Reading text size

General & tools → Reading text size sets the text size of the landing page, this guide, the help panel, every settings page and the dialogs: Small, Medium (the default, about 15.5 px body text, close to the 14–16 px that Windows and the web use for reading) or Large. The workspaces (the grids, toolbars and line panels of Phase 1, Phase 2, the FOMOD builder, NPC Revoice, Voiced Books and the WAV to LIP tool) keep their compact size so more lines fit.

Background image

General & tools → Appearance → Background image puts an image of your own behind every page: Choose image… picks a PNG, JPG, WebP, GIF or BMP, and Reset brings back the plain background. Each page keeps its usual shade over the image, while cards, sections and lists stay solid, so the text stays readable. Pages you work in (a mod's lines, a patch, a revoice project, the FOMOD editor and this guide) stay fully solid. The Global Settings sidebar gets the same light see-through shade as the page header above it. Shade (Lighter, Normal, Darker) shows more or less of the image. Wide images (16:9 or wider) fit best, since the image is cropped to fill the window. The image is copied into DBVO Studio's own folder on this computer (%LOCALAPPDATA%\DBVOStudio\UserFiles), so moving the original doesn't break it, but it doesn't travel with the library to another PC.

Other switches

Appearance changes the colour theme and holds the background image (above). Voice lines with Player Names (off by default) keeps <Alias=Player> lines out of generation. Confirmation message when mass-generating lines shows a cost summary before any batch. Categories sort mods and patches and become the default FOMOD pages; they never change folder paths. Local voice engines holds the VoxCPM and OmniVoice server addresses.

Phase 1: Import Mods

Phase 1 turns a mod's plugins into DBVO-ready player lines. You review the lines DBVO's script flags, decide what is voiced and what goes into the DBVO Fix plugin, then continue to Phase 2. The work is shared by every voice pack, so you do it once per mod.

Add mods

  • + New mod creates one mod: a name, an optional version and a category. Then drop its plugins on the mod page.

  • + Add many mods…, or dropping plugins anywhere on the Mods list, opens a table with one row per plugin. Plugins given the same mod name become one mod, and a file such as "Mod - Patch.esp" dropped next to "Mod.esp" is named after it automatically. Paste names and categories fills the table from lines like Plugin.esp | Mod Name | Category.

Create mods and import makes a backup, imports each mod and reports missing masters and unreadable strings. It refuses while a row has no name, a name already exists, one mod's plugins sit in different categories, or a file appears twice.

The Mods list groups cards by category. Each card shows its topic lines, how many go into a DBVO Fix plugin, its player-name lines, and a red flagged to review badge until every flagged line has been opened. Once a mod is fully reviewed it shrinks to a chip with its topic line count; the category header says all reviewed ✓ or how many are left to review. NPC Revoice, Voiced Books and Player Grunts list their finished projects as chips the same way.

Add or update files in a mod

On a mod's page, drop files on the + drop file / update chip or use Add plugins or topic files ▾.

  • Plugins (.esp, .esm, .esl) are read on their own, without xEdit or a load order.

  • Topic files (.txt) are for mods without a plugin, such as old mods or player-name collections. Their lines are checked the same way and kept as written; no DBVO Fix plugin can be made from them.

  • A newer version of a plugin already in the mod updates it and keeps your edits. Lines are matched by record and field, and the message reports kept, changed, new and removed lines.

  • An earlier DBVO Fix plugin (a file that only overrides another plugin's dialogue) is recognised when dropped. You can import its texts, add it as a plugin anyway, or skip it. Import existing DBVO Fix plugin… does the same on purpose. Once imported, a Fix chip shows next to that button: hover it and it turns into ✕, click it to remove the import. The lines it changed get their earlier text back; lines you edited by hand afterwards keep your edit, and the file itself is not touched.

If lines can't be read, a banner says why. Missing masters lists each with a find on Nexus link and Upload masters…; a localized plugin needs Add strings files….

Every list in the app sorts by a column: click its title to sort ascending (▲), again for descending (▼), and a third time for the usual order. The choice is remembered per list.

Pick the plugin in the Plugin dropdown, which also shows fix N or clean and how many lines are left to review. The grid shows each line's status, its original text, the final in-game line, and three choices: Fix, ♪ Voice and Exclude (⊘).

Iterations of alias lines

A line like "How about <Alias=SonsMajorHoldCapital>?" shows in game with a name or place where the alias is, so DBVO can only match it when every way it can read is in the topic file. Instead of rewording the line, add iterations: the line written out once for each value. The line itself stays as the mod wrote it (unless you edit it too), and each iteration becomes its own topic line and voice file in Phase 2.

  • + Iter. next to a line in the list, or Add iterations… in the line panel, opens the dialog for one line. Type what each alias can be, separated by commas (Whiterun, Markarth, Riften…). Every combination is written out for you, <Alias.Cap=…> gets a capital letter, and you can add your own lines too.

  • Iterations for N alias line(s)… in the status bar does the same for every alias line shown (or the ticked ones), with Add to existing or Replace existing.

  • The values you type are remembered per mod, so the next line with the same alias is filled in for you.

  • The Alias lines and With iterations filters find them; a line with iterations no longer counts as flagged, and its BROKEN LINE label becomes ITERATIONS ADDED. The dialog warns when an iteration is over 150 characters.

Click a row to open it in the panel. Opening a flagged line marks it reviewed. The panel explains the problem, counts characters against 150, and checks your text against the script as you type, offering Use the script's version when it can fix it.

In the grid, ✓ takes the script's suggestion and ↶ goes back to the original. Filter chips (In DBVO Fix, Not voiced, Flagged, Not reviewed, Player names, Changed in mod, and more) only appear when they match something; the search box looks in text, FormID and EditorID.

Fix, Voice and Exclude

Every line has two independent choices and one way out.

  • Fix writes your edited text to DBVO Fix - <plugin>.esp, so the subtitle changes in game. It is greyed out while the text is unchanged.

  • ♪ Voice puts the line in the topic file, so Phase 2 generates it.

  • Exclude leaves the line out of both.

A chip with a thicker outline is your own choice rather than the default; Back to defaults in the panel forgets it. Tick rows to act on many at once:

Approve confirms both choices as they stand and marks the rows reviewed. Mark reviewed marks them without changing anything.

Player-name lines

These show the player's chosen name, so they can't be voiced in an ordinary patch. They are left unvoiced by default (Global Settings → Voice lines with Player Names changes that). Export N player-name line(s), or Export this line to Downloads in the panel, saves them as a topic .txt in your Downloads folder for your player-name patches.

Continue to Phase 2

Continue to Phase 2 → writes the topic files and DBVO Fix plugins and opens the mod's DBVO Patch for your voice pack. If flagged lines were never opened, it asks first: Show them filters the grid to those lines; Continue anyway leaves them with the game's text, unvoiced.

A DBVO Fix plugin is only made when at least one line needs fixing; a clean plugin gets none. Export… ▾ writes the same files to any folder, only for use outside the app. Remove plugin… and Delete (the whole mod) make a backup first; patches drop the removed lines when they next open, but keep their takes in case the lines return.

Phase 2: DBVO Patching

A DBVO Patch is one voice pack × one or more Phase 1 mods. You generate a take for every line, keep the takes you like, and export WAV + LIP and .fuz files. Every take is trimmed, given a LIP file and kept in the Library, so regenerating never loses earlier work.

The patch list

The page has two lists side by side, each with its own voice pack filter, so you can compare voice packs. A patch with work left (lines without a take, Phase 1 lines to review, or warnings) is a full card: the Phase 1 state (P1 ✓, or how many lines still need review), progress, lines with a take out of lines to voice, and the characters still to generate (about one ElevenLabs credit each). A finished patch shrinks to a small chip with its line count, so a long list stays short; click it to open the patch. Each category header shows its patches and lines, and all complete ✓ or how many have work left. All · Work left · Complete above each list picks what to show. Empty categories are listed on one line at the bottom. The Voice Changer page works the same way.

  • + New DBVO Patch: pick the voice pack and one or more mods; several mods make an all-in-one patch. Phase 1's Continue to Phase 2 creates or opens a patch for you.

  • Drag a patch onto another category to move it, card or chip, also onto a name in the empty categories line. While you drag, the patch name follows the pointer and the category under it lights up with Move to …; after the drop it shows Moving… until it is saved. This changes the mod's category, which all its patches share.

The patch page

Opening a patch re-reads Phase 1 (so does ⟳ Refresh). Lines that left Phase 1 have their takes parked in case they return, and WAV + LIP files already in the patch's WAV + LIP folder are adopted as take #1. With thousands of lines that takes a few seconds, so a Loading voice lines screen with a progress bar shows until it is done; the same screen shows after you change the patch's folders in Folders & options. Pointing the patch at another WAV + LIP folder reads that folder in: a line that already has takes gets the new folder's file as a new take in use (unless it has the same audio already), and its earlier takes stay.

From top to bottom: the header (credits, voice pack switch, Voice Changer, Folders ▾, Delete), the engine toolbar, the tag bar, banners, filters, the grid with the line panel, and the status bar: Review, Check takes, Import ▾, Takes ▾, Export ▾ and Generate options ▾. Folders ▾ holds Folders & options… and opens the patch's WAV + LIP, final and DBVO Fix folders.

The toolbar

The toolbar edits the voice pack's engine settings and saves every change. With Lock engine settings on, it shows 🔒 locked and refuses changes.

  • ElevenLabs: Voice (⟳ reloads voices and models), Model (· tags marks v3/v4), Stability (Creative / Natural / Robust on tag models), Similarity, Style and Speaker boost (non-tag models only), Speed, Language, Read numbers, and Output ▾, which holds Format, Seed and Concurrent so the toolbar stays on one line.

  • VoxCPM / OmniVoice: the reference voice, a server status badge, and the engine's own settings.

  • Concurrent should match your ElevenLabs plan; the app slows down by itself on "too many requests".

  • The credits ring in the page head shows what is left this period, when it resets, and roughly what this patch still needs.

Spoken text and tags

The Filename comes from the in-game line set in Phase 1 (P1 marks lines edited there). The Spoken text is what the voice says, and editing it never changes the filename. Blue text differs from the in-game line; the arrow at its start restores it.

The line panel on the right keeps to what you need: the line (one box, Line (same in game), when Phase 1 didn't change it), the file name with its .wav, .lip and .fuz tags and a copy button, the spoken text (it grows as you type), then AI tag, Restore, 🎙 Record and New take, and the takes with ⚠ or ✓ from Check takes on each row. Hover a take for its engine, model and settings.

  • Tag chips insert at the cursor of the box you are typing in. With rows ticked instead, they go at the start of each ticked line; Shift-click removes them.

  • [custom tag] + Enter adds any tag to the ticked rows.

  • AI Auto Tag asks your AI provider for tags on the ticked lines. Each suggestion shows the added tags with ✓ to accept or ✕ to undo.

  • Add a [tag] to all shown… adds or removes tags on every line in the current filter, optionally only where the spoken text contains a phrase, the original line contains a cue such as (Intimidate), or the line is longer or shorter than a length. The voice pack's tags (and a [custom tag] box) sit above the Tags box: click one to put it in. The panel on the right lists the lines it will be added to (or removed from) as you change the conditions, and the count under the box says Will be added to N of M lines.

  • Find and replace in all shown… opens the classic find and replace over the spoken text of every line in the current filter. Type what to find and what to put instead (leave it empty to delete), tick Match case or Whole words only, and put [tags] into either box with the tag buttons or the [custom tag] box. The dialog counts the matches and shows the first changes before you press Replace. The same button is in NPC Revoice (tag bar), Voiced Books (next to the search box, over the spoken text of the books shown) and Phase 1 (next to the search box, over the in-game text, which goes into the DBVO Fix plugin like any edit).

Tags are an ElevenLabs v3/v4 feature; other engines ignore them.

Takes

The Take column shows the take in use and the total, such as #2/2; click it to open the line's takes.

  • ▶ plays a take; double-clicking a row plays the take in use.

  • Use makes a take the one exported and fuzzed.

  • ★ keeps a take as a variant. With DBVO 2.0 naming every kept take is exported as a variant; with none kept, the take in use is. Legacy naming exports one take per line.

  • 🗑 deletes a take and its files. Keep only the used take deletes the rest except kept ★ takes; Takes ▾ does the same for ticked lines or the whole patch. Takes ▾ → Delete all takes · omitted lines deletes every take of the omitted lines (kept ★ takes stay); those lines are never exported, and files exported for them earlier are offered for removal at the next export.

  • A small fuz mark next to the take number means the take in use is an imported .fuz, kept as it is.

  • The folder icon opens the line's takes folder.

Exclude, flag and omit

  • 🚫 Exclude: the line is not generated or exported and doesn't count as missing.

  • ⚑ Flag: stays until you clear it. Collect lines to redo, then pick Flagged in Generate options ▾.

  • Omitted: a ticked reference topic file already has the line. Generate anyway in the panel overrides this for one line. The All non-omitted filter, next to All, shows every line except the omitted ones. If you ticked a reference only after generating, Takes ▾ → Delete all takes · omitted lines removes the takes the omitted lines no longer need.

With rows ticked, Ticked (N) ▾ in the status bar excludes, includes or flags them, or clears the ticks. With none ticked it shows Flags ▾, which clears every flag.

Voice Changer

Turn on the Voice Changer only when the mod is already DBVO-patched with another voice. It converts that pack's WAV or .fuz files into this voice with ElevenLabs speech-to-speech, so delivery and timing come from the source and a new .lip is made from the text. Add the other pack's folders when asked; files are matched by Legacy and DBVO 2.0 names. Lines with no source file, usually added by a mod update, stay unvoiced unless you switch on Generate lines without a source with text-to-speech. It is billed by audio length, not characters.

Checking takes

Check takes (in the status bar) listens to every take in use (with DBVO 2.0 names, also the kept ★ variants that are exported) with Whisper and measures it. A line is flagged when the words heard differ too much from the spoken text, when the take is very quiet (below −30 LUFS), or when it clips (true peak above −0.5 dBTP). Tags, *actions* and punctuation are ignored when comparing words.

Before it starts, the Check takes dialog asks what to check, and remembers your choices:

  • Which takes: only the unchecked ones (after a first run) or all.

  • Check the words, with the Whisper model (large-v3 turbo by default; small.en and base.en are faster still; large-v3 is the slow, careful WAV to LIP model), the language (English skips detection) and quick decoding (one pass per take, several times faster on short lines).

  • Check loudness and clipping.

  • Sharp peaks: flags takes whose loudest peak stands far above the speech level (12, 14 or 16 dB), the hard t, d and g bursts that crackle at a high in-game volume but are too short to clip. Post-processing ▾ → Soften peaks fixes them; see Soften peaks.

  • Check the start of each take: flags the stray burst some ElevenLabs v4 takes open with, a short loud sound right at the start, then silence, then the line. Strict, Normal or Relaxed sets how readily it flags. It only flags; the audio is never changed. A take you approved in Review is not flagged again.

With the words off, the check runs without Whisper and takes moments. The bar at the top counts the lines checked against the total; hover it to see where Whisper runs (GPU or CPU) and how many takes per second it checks. Cancel stops the check and keeps the results so far. Afterwards the QA column, left of Take, shows ⚠ for flagged and ✓ for passed takes; click its title to sort the flagged ones to the top (Phase 2 and NPC Revoice).

The Take column shows ⚠ for a flagged take and ✓ for one that passed; hover it to see what Whisper heard, the score, loudness and peak. The QA flagged filter lists the flagged lines, which pairs well with Review. A new take clears its line's result, and Generate options ▾ → Check found problems makes a new take for every flagged line. The check uses the Whisper model from Global Settings → Tools and costs no credits.

Recording a take

🎙 Record in the line panel records a take with your microphone. The microphone and its level meter start when the recorder opens, so the static some microphones make when switched on has passed before you press Record. After recording, drag Start and End to trim, and Play selection to hear it.

  • Keep my recording saves it as a new take: trimmed, levelled, faded out and given a .lip from the spoken text.

  • Convert to <voice> and keep first sends it through ElevenLabs speech-to-speech into the patch's voice, so your timing and delivery carry over. It uses the Voice Changer settings and is billed by audio length. The button explains itself when it can't be used, for example without an ElevenLabs voice.

If the meter stays flat, check that Windows lets apps use the microphone (Settings → Privacy & security → Microphone).

Splitting into parts

The voice engines accept only so much text per request, so long books are read in parts and joined at export. Part length sets the wanted length (about 2,000 characters) and the longest part (2,500); the model's own limit is shown next to it. Parts break at paragraphs first, then at the ---- separators, then at sentence ends, never inside a sentence, and never after an abbreviation or an initial.

In the editor, each break has ◀ and ▶ to move it one sentence earlier or later, and ✕ to remove it. Break at cursor adds one at the sentence end nearest the cursor, and Auto places them automatically again. Parts whose text didn't change keep their takes; the others show as edited since take.

  • Find missing files…: pick a folder; files that were moved are found again by name.

Effects, subtitles, loudness and variants

The effect switch (between a line's length and its arrows) puts the project's toggle effect on the line; its label names that effect. By default it is Inner thoughts, the reverb for thoughts and narration: Audacity's Reverb with room size 81, reverberance 23, HF damping 62, tone low 16, tone high 19, pre-delay 99 ms, dry 0 dB and wet -4 dB, after one second of silence is added at the end (the line's own length when it is shorter) so it rings out. ⋯ → Effect… picks any other: reverbs (small room, hall, cave, distant, echo), filters (radio, telephone, muffled, underwater) and three custom slots you fill in yourself (Setup & export → Effects), and voices (telepathy, ghostly whisper, ghost, Dwemer automaton, Daedric Prince). … all lines in the event panel does the whole event at once. The WAV file itself changes, so it sounds that way wherever you open it; the original is kept in the project, switching the effect off puts it back exactly, and another effect always starts again from the original. A file changed after the effect was added is only replaced after you confirm; removing or replacing such a line also puts the original back. Effects work on WAV files only.

Setup & export → Effects lists the project's effects: change a reverb's numbers or a filter, duplicate one to make your own, pick the one the switch uses (Use for the toggle), or reset them.

Trim and fade… (⋯) cuts the start or end and fades in or out. The file isn't changed: the cut is used when listening and exporting (✂ on the line), and Reset takes it away.

Make variants… (⋯) adds new lines made from one: a little higher or lower and faster or slower (±3 % by default, spread evenly), so a pool doesn't repeat the same grunt.

Loudness shows on each line once measured (new lines are measured by themselves; Measure loudness in the bottom bar measures all). A line more than 4 LU from the pack's middle shows in red, and Check lists it as too loud or too quiet compared with the pack (and lines that clip). Loudness matching on export evens them out when it is on.

Whisper subtitles (event panel) and Whisper all subtitles (bottom bar) let Whisper fill in every empty subtitle, with one model load for all; check them before exporting.

Apply subtitles… (a line's ⋯ menu) sets the subtitle of any line, also imported files and recordings. Suggest with Whisper listens to the line (with the WAV to LIP Tool's Whisper settings) and fills in what it heard; check it before saving. SPVS writes the subtitle as a .toml next to the audio; PC Head Tracking shows no subtitles, but .fuz files get their lip sync from the text.

Subtitles .toml (above the blocks) opens one file with every line's subtitle in your text editor. Edit the texts, save, and come back to DBVO Studio: the changes are read in.

Recording shows the event's name to read, its description below, and a Subtitle field. After each take Whisper suggests the words (while the field is still empty); Suggest with Whisper asks again for the trimmed part.

Text-to-speech workspace

Text-to-speech in the event panel (any event, grunts too), T on a shout part, or ⋯ → New tries with text-to-speech… on a line opens a workspace for trial and error. It uses the project's DBVO voice pack (ElevenLabs, VoxCPM or OmniVoice).

  • Subtitle: what the game shows (SPVS writes it to the .toml). PCHT shows no subtitles; the text is kept with the line.

  • Spoken text: what the voice gets, with [tags] and formatting (punctuation, …, CAPS). The tag chips (the voice pack's tags, or OmniVoice's [laughter] [sigh] [gasp]) insert at the cursor, and any tag can be typed. ElevenLabs v3 and v4 models and OmniVoice perform the tags; VoxCPM would read them aloud, so they are left out for it unless Send [tags] is on.

  • Stability and Speed (ElevenLabs; Speed for OmniVoice) apply to the next try only; the voice pack stays as it is. Each try gets a new seed, so the same text gives a new take (Keep the voice pack's seed to repeat one).

  • Generate try (Ctrl+Enter) adds a try and plays it. Every try keeps its text and settings; ▶ plays it again, 🗑 throws it away. Change the text or the settings and try again as often as you like.

  • Pick a try and Save to … puts it on the event (or the shout part, or replaces the line you were redoing). Only then does the event change.

Close keeps the texts and the tries with the project: the event panel shows "▶ N unsaved tries" to carry on later, also after a restart. Discard all (click twice) throws them away.

Custom events

The event lists are data, not code. Custom events… adds events the list doesn't have yet:

  • SPVS: a name, a category, the Audio Util category key SPVS's scripts ask for (e.g. SwimStart) and its folder under the voice slot. Import… also takes an SPVS Audio Util .toml: its categories become events. Setting the SPVS folder already reads the installed SPVS's own list, which covers most new events by itself.

  • PCHT: a name, a category, the sound descriptor (SNDR) another plugin adds to PCHT's voice events, and its folder. PCHT's own events are all listed already.

Custom events are kept in the library (grunts\custom-events.json), shared by every project of the mod, and Export… saves them to share. Imports are checked: missing keys or folders, characters a game path can't use, a key or folder the mod already has, and duplicates are reported and skipped. When an installed SPVS update adds an event you defined yourself, its own definition is used.

Player Grunts limitations

  • A mod only plays the events its own scripts ask for. A custom SPVS event plays once an SPVS version that asks for it is installed; an event that needs new SPVS or PCHT scripts can't be added from here.

  • PCHT keeps one default voice: two default PCHT packs that change the same descriptors override each other. Use Multi Voice Packs for several.

  • The FormList Manipulator lines name records by editor ID, as the MPCHT Toolkit does.

  • "PC Head Tracking - More Voices.esp" (Bella) isn't supported as a source.

  • Discovered · Specific location lines for locations added by mods also need an entry in SPVS's location config (Discovered\Specific\Config), which the tool doesn't write.

Backups

A backup zips every project and settings file in the Library, named with the date, time and reason. It does not contain audio.

  • Automatic before importing mods, deleting a mod, plugin, patch, FOMOD or revoice project, generating, and building a FOMOD. Generation and build backups are marked -auto-, made at most every 10 minutes, and rotated separately.

  • Backups to keep sets how many of each kind stay; Back up now makes one on demand.

  • To restore, close the app and unzip the backup over the Library folder. Deleting a patch or revoice project deletes its takes, so a restore brings the project back without its audio.

  • To move the Library, use Change… rather than moving the folder by hand, and keep the old folder until you have checked the new one.

What deleting does

  • Deleting a Phase 1 mod removes its Phase 1 work from the Library: the line review, your text edits, the DBVO Fix decisions and the copies of its plugins. Your original plugin files stay, and so does everything already exported (DBVO Fix plugins, topic files, WAV, LIP, .fuz). DBVO Patches that read the mod lose its lines, but keep their takes; import the mod again and tick it in the patch's Folders & options → Mods to get them back. The delete dialog names the patches that use the mod.

  • Deleting a DBVO Patch deletes the patch and every take in it (the WAV and LIP files kept in the Library). Files already exported to your folders stay; a new patch pointed at the same WAV + LIP folder adopts them as take #1.

  • Both make a backup of the project files first. Backups hold no audio, so takes deleted with a patch can't be restored from a backup.

Effects on takes (Phase 2 and NPC Revoice)

The line panel has an Effect list with the same reverbs, filters and voice effects as the Player Grunts Tool. Tick lines and use Post-processing ▾ → Effects… (on the tags row in Phase 2, next to Open folder in NPC Revoice) to put one on all of them. It goes on every take of the line and on new takes as they are made; lines with an effect show an E next to their take, and clicking the E takes it off again (the dry takes are kept, and the .lip files stay as they are). Effects come out as loud as the line went in: the result is matched to the dry take's loudness (EBU R128) with a soft peak limit, so a reverb or filter doesn't make a line jump out or drop away.

Soften peaks

Some voices have hard consonants (t, d, g, k) whose bursts stand far above the rest of the line. They are too short to clip, but at a high in-game volume they crackle. Soften peaks turns only those bursts down, over a few milliseconds, then brings the line back to its own loudness. Nothing is delayed, so the .lip still fits.

Which strings Phase 1 reads

A localized plugin's texts come from its strings files, and DBVO finds each voice file by the text the game shows, so Phase 1 reads what loads last in the game. For a plugin of the game itself (Skyrim.esm, the DLCs, Creation Club) that is loose Data\Strings when there are any, otherwise the game's own archives: the wording xEdit shows. Strings next to the plugin, kept with the mod, or in the Global Settings strings folder come after that. A strings file that doesn't fit the plugin (an old or mismatched copy that lacks some of its texts) is passed over for the next one that has them all.
