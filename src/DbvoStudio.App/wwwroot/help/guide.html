Introduction

DBVO Studio takes a Skyrim mod from its plugin to a finished, installable Dragonborn Voice Over (DBVO) voice pack in three phases. Two stand-alone tools sit beside them. The top bar shows the phases in order; Other Tools ▾ opens the tools and ⚙ Global Settings holds everything that applies to the whole app.

Phase 1 decides what is said, Phase 2 decides how it sounds, and Phase 3 decides how it is installed. You can export at any stage and skip the FOMOD altogether.

The guide follows the same order: setup, the three phases, the two tools, a reference of greyed-out buttons, then files and troubleshooting. Every button in the app also has a tooltip. The screenshots use sample data: the base game plugins as the mod, and a voice pack called Sample Voice.

The landing page and help

Clicking DBVO Studio at the top left opens the landing page. It greets you (with a different welcome and a word from M’aiq the Liar each time DBVO Studio opens) and offers what to do next: make DBVO patches, revoice NPCs, build a FOMOD, make lip sync, set up the studio or read this guide.

  • The left side counts your mods, patches and voiced lines, and checks the studio: the Library path, the five tools, your ElevenLabs credits and AI auto-tagging. An amber chip needs attention; click it to go to the setting.

  • Pick up where you left off shows the four projects you opened most recently (patches, mods, FOMODs and revoice projects) with their progress. Click one to open it.

Help is built in. The small ? buttons next to page titles, toolbars, settings and dialogs open this guide at the matching section in a side panel; click the same ? again, or press Esc, to close it. Every button and setting also explains itself when you rest the mouse on it. ? Guide in the top bar, or F1, opens the whole guide with a contents list and search.

Getting started

After installing, and before your first mod, do four things in ⚙ Global Settings: choose the Library location, check the tools, add your ElevenLabs key, and create a voice pack. Everything there saves as you change it.

1. Install and launch

Unzip the build anywhere and run DBVO Studio.exe. It needs Windows 10 or 11 with the Microsoft Edge WebView2 runtime, which Windows already includes. ffmpeg and 7-Zip ship in the app's Tools folder.

2. Choose the Library location first

The Library holds every project, take and backup. It starts in Documents\DBVO Studio, and moving it later means copying every take, so set it before you start: General & tools → Library → Change….

  • Keep the path short, such as D:\DBVO Studio Library. Windows limits paths to 260 characters and DBVO file names are long.

  • Use the drive your WAV + LIP files are on. On the same drive, a take and its exported copy are hardlinked: one file on disk, no extra space, written instantly. Across drives every file is copied.

  • Change… takes an empty folder (your Library is copied into it) or a folder that already holds a Library (used as it is). The app restarts afterwards.

3. Check the tools

The Tools section shows a ✓ or ✕ badge per tool, and ⓘ explains how to get each one. Empty or broken paths are filled in on every start from the included copies, an installed DBVO Voice Pack Maker, your Skyrim folder and the default Steam folder.

Under Plugins, set the Base game plugins folder to your game's Data folder. Plugins are read with Skyrim.esm and the DLCs as masters, and the Creation Kit tools are then found too. Localized plugins also need the Strings folder and Strings language.

4. Add your ElevenLabs key

Paste the key under ElevenLabs → API key and click Save key; it is stored encrypted for your Windows user. Test shows your plan and the characters used.

5. Create a voice pack

Open Voice packs → + New voice pack. If you skip this, Continue to Phase 2 sends you here and opens Phase 2 right after.

Optional settings

None of these are needed to start; come back to them when you want them.

AI auto-tagging

ElevenLabs has no API for its Enhance button, so AI Auto Tag (Phase 2 and NPC Revoice) asks an AI model to add [tags] without changing any words; suggestions that change words are thrown away. Pick a preset (Ollama or LM Studio, free on your PC; OpenAI or Anthropic, paid), follow its numbered steps, add a key for online providers, then Test connection.

Pronunciation

A global dictionary used by every voice pack. Sounds like respells a word and works with every engine; IPA is exact, but only ElevenLabs v3/v4 and Flash v2 read it. Whole word and Match case narrow the match. Only the spoken text changes, never subtitles or file names. Import and export work with DBVO Voice Pack Maker 2.7.0, CSV and .pls files.

Omit references

Topic .txt files of lines every user already has, such as the base game voice pack. In a patch, lines found in a ticked reference are omitted, so you never voice a line twice. Only add packs every user installs, never optional mods.

Start page

General & tools → Start page decides what you see when DBVO Studio opens: the Landing page (the default) or Where I left off, the page you had open last time. The DBVO Studio logo at the top left always opens the landing page.

Background image

General & tools → Appearance → Background image puts an image of your own behind every page: Choose image… picks a PNG, JPG, WebP, GIF or BMP, and Reset brings back the plain background. Each page keeps its usual shade over the image, while cards, sections and lists stay solid, so the text stays readable. Pages you work in (a mod's lines, a patch, a revoice project, the FOMOD editor and this guide) stay fully solid. The Global Settings sidebar gets the same light see-through shade as the page header above it. Shade (Lighter, Normal, Darker) shows more or less of the image. Wide images (16:9 or wider) fit best, since the image is cropped to fill the window. The image is copied into DBVO Studio's own folder on this computer (%LOCALAPPDATA%\DBVOStudio\UserFiles), so moving the original doesn't break it, but it doesn't travel with the library to another PC.

Other switches

Appearance changes the colour theme and holds the background image (above). Voice lines with Player Names (off by default) keeps <Alias=Player> lines out of generation. Confirmation message when mass-generating lines shows a cost summary before any batch. Categories sort mods and patches and become the default FOMOD pages; they never change folder paths. Local voice engines holds the VoxCPM and OmniVoice server addresses.

Phase 1: Import Mods

Phase 1 turns a mod's plugins into DBVO-ready player lines. You review the lines DBVO's script flags, decide what is voiced and what goes into the DBVO Fix plugin, then continue to Phase 2. The work is shared by every voice pack, so you do it once per mod.

Add mods

  • + New mod creates one mod: a name, an optional version and a category. Then drop its plugins on the mod page.

  • + Add many mods…, or dropping plugins anywhere on the Mods list, opens a table with one row per plugin. Plugins given the same mod name become one mod, and a file such as "Mod - Patch.esp" dropped next to "Mod.esp" is named after it automatically. Paste names and categories fills the table from lines like Plugin.esp | Mod Name | Category.

Create mods and import makes a backup, imports each mod and reports missing masters and unreadable strings. It refuses while a row has no name, a name already exists, one mod's plugins sit in different categories, or a file appears twice.

The Mods list groups cards by category. Each card shows its topic lines, how many go into a DBVO Fix plugin, its player-name lines, and a red flagged to review badge until every flagged line has been opened.

Add or update files in a mod

On a mod's page, drop files on the + drop file / update chip or use Add plugins or topic files ▾.

  • Plugins (.esp, .esm, .esl) are read on their own, without xEdit or a load order.

  • Topic files (.txt) are for mods without a plugin, such as old mods or player-name collections. Their lines are checked the same way and kept as written; no DBVO Fix plugin can be made from them.

  • A newer version of a plugin already in the mod updates it and keeps your edits. Lines are matched by record and field, and the message reports kept, changed, new and removed lines.

  • An earlier DBVO Fix plugin (a file that only overrides another plugin's dialogue) is recognised when dropped. You can import its texts, add it as a plugin anyway, or skip it. Import existing DBVO Fix plugin… does the same on purpose.

If lines can't be read, a banner says why. Missing masters lists each with a find on Nexus link and Upload masters…; a localized plugin needs Add strings files….

Review the lines

Pick the plugin in the Plugin dropdown, which also shows fix N or clean and how many lines are left to review. The grid shows each line's status, its original text, the final in-game line, and three choices: Fix, ♪ Voice and Exclude (⊘).

Click a row to open it in the panel. Opening a flagged line marks it reviewed. The panel explains the problem, counts characters against 150, and checks your text against the script as you type, offering Use the script's version when it can fix it.

In the grid, ✓ takes the script's suggestion and ↶ goes back to the original. Filter chips (In DBVO Fix, Not voiced, Flagged, Not reviewed, Player names, Changed in mod, and more) only appear when they match something; the search box looks in text, FormID and EditorID.

Fix, Voice and Exclude

Every line has two independent choices and one way out.

  • Fix writes your edited text to DBVO Fix - <plugin>.esp, so the subtitle changes in game. It is greyed out while the text is unchanged.

  • ♪ Voice puts the line in the topic file, so Phase 2 generates it.

  • Exclude leaves the line out of both.

A chip with a thicker outline is your own choice rather than the default; Back to defaults in the panel forgets it. Tick rows to act on many at once:

Approve confirms both choices as they stand and marks the rows reviewed. Mark reviewed marks them without changing anything.

Player-name lines

These show the player's chosen name, so they can't be voiced in an ordinary patch. They are left unvoiced by default (Global Settings → Voice lines with Player Names changes that). Export N player-name line(s), or Export this line to Downloads in the panel, saves them as a topic .txt in your Downloads folder for your player-name patches.

Continue to Phase 2

Continue to Phase 2 → writes the topic files and DBVO Fix plugins and opens the mod's DBVO Patch for your voice pack. If flagged lines were never opened, it asks first: Show them filters the grid to those lines; Continue anyway leaves them with the game's text, unvoiced.

A DBVO Fix plugin is only made when at least one line needs fixing; a clean plugin gets none. Export… ▾ writes the same files to any folder, only for use outside the app. Remove plugin… and Delete (the whole mod) make a backup first; patches drop the removed lines when they next open, but keep their takes in case the lines return.

Phase 2: DBVO Patching

A DBVO Patch is one voice pack × one or more Phase 1 mods. You generate a take for every line, keep the takes you like, and export WAV + LIP and .fuz files. Every take is trimmed, given a LIP file and kept in the Library, so regenerating never loses earlier work.

The patch list

The page has two lists side by side, each with its own voice pack filter, so you can compare voice packs. Each row shows the Phase 1 state (P1 ✓, or how many lines still need review), progress, lines with a take out of lines to voice, and the characters still to generate (about one ElevenLabs credit each).

  • + New DBVO Patch: pick the voice pack and one or more mods; several mods make an all-in-one patch. Phase 1's Continue to Phase 2 creates or opens a patch for you.

  • Drag a patch onto another category to move it. This changes the mod's category, which all its patches share.

The patch page

Opening a patch re-reads Phase 1 (so does ⟳ Refresh). Lines that left Phase 1 have their takes parked in case they return, and WAV + LIP files already in the patch's WAV + LIP folder are adopted as take #1.

From top to bottom: the header (credits, voice pack switch, Voice Changer, Folders & options…, Delete), the engine toolbar, the tag bar, banners, filters, the grid with the line panel, and the status bar with the generate and export buttons.

The toolbar

The toolbar edits the voice pack's engine settings and saves every change. With Lock engine settings on, it shows 🔒 locked and refuses changes.

  • ElevenLabs: Voice (⟳ reloads voices and models), Model (· tags marks v3/v4), Stability (Creative / Natural / Robust on tag models), Similarity, Style and Speaker boost (non-tag models only), Speed, Language, Read numbers, and Output ▾, which holds Format, Seed and Concurrent so the toolbar stays on one line.

  • VoxCPM / OmniVoice: the reference voice, a server status badge, and the engine's own settings.

  • Concurrent should match your ElevenLabs plan; the app slows down by itself on "too many requests".

  • The credits ring in the page head shows what is left this period, when it resets, and roughly what this patch still needs.

Spoken text and tags

The Filename comes from the in-game line set in Phase 1 (P1 marks lines edited there). The Spoken text is what the voice says, and editing it never changes the filename. Blue text differs from the in-game line; the arrow at its start restores it.

  • Tag chips insert at the cursor of the box you are typing in. With rows ticked instead, they go at the start of each ticked line; Shift-click removes them.

  • [custom tag] + Enter adds any tag to the ticked rows.

  • AI Auto Tag asks your AI provider for tags on the ticked lines. Each suggestion shows the added tags with ✓ to accept or ✕ to undo.

  • Add a [tag] to all shown… adds or removes tags on every line in the current filter, optionally only where the spoken text contains a phrase, the original line contains a cue such as (Intimidate), or the line is longer or shorter than a length.

Tags are an ElevenLabs v3/v4 feature; other engines ignore them.

Takes

The Take column shows the take in use and the total, such as #2/2; click it to open the line's takes.

  • ▶ plays a take; double-clicking a row plays the take in use.

  • Use makes a take the one exported and fuzzed.

  • ★ keeps a take as a variant. With DBVO 2.0 naming every kept take is exported as a variant; with none kept, the take in use is. Legacy naming exports one take per line.

  • 🗑 deletes a take and its files. Keep only the used take deletes the rest except kept ★ takes; Takes ▾ does the same for ticked lines or the whole patch.

  • The folder icon opens the line's takes folder.

Exclude, flag and omit

  • 🚫 Exclude: the line is not generated or exported and doesn't count as missing.

  • ⚑ Flag: stays until you clear it. Collect lines to redo, then press Flagged lines.

  • Omitted: a ticked reference topic file already has the line. Generate anyway in the panel overrides this for one line.

With rows ticked, Ticked (N) ▾ in the status bar excludes, includes or flags them, or clears the ticks. With none ticked it shows Flags ▾, which clears every flag.

Voice Changer

Turn on the Voice Changer only when the mod is already DBVO-patched with another voice. It converts that pack's WAV or .fuz files into this voice with ElevenLabs speech-to-speech, so delivery and timing come from the source and a new .lip is made from the text. Add the other pack's folders when asked; files are matched by Legacy and DBVO 2.0 names. Lines with no source file, usually added by a mod update, stay unvoiced unless you switch on Generate lines without a source with text-to-speech. It is billed by audio length, not characters.

Review

▶ Review in the status bar turns the grid into a listening session: each line plays as you reach it, and the keys do the rest. Approved lines get a green edge, and the Not approved filter shows what is left. End review or Esc stops it; approvals are kept.

KeyDoes

The Autoplay switch on the bar turns off playing on arrival. Keys are ignored while you type in a box or a dialog is open. Approve in the line panel does the same as A. An approval belongs to the take you heard: a new take, or choosing another with Use, clears it. Approving is optional; exports include every line unless you turn on approved-only export in Folders & options.

Checking takes

More ▾ → Check takes listens to every take in use (with DBVO 2.0 names, also the kept ★ variants that are exported) with Whisper and measures it. A line is flagged when the words heard differ too much from the spoken text, when the take is very quiet (below −30 LUFS), or when it clips (true peak above −0.5 dBTP). Tags, *actions* and punctuation are ignored when comparing words.

The Take column shows ⚠ for a flagged take and ✓ for one that passed; hover it to see what Whisper heard, the score, loudness and peak. The QA flagged filter lists the flagged lines, which pairs well with Review. A new take clears its line's result; More ▾ → Clear check results clears them all. The check uses the Whisper model from Global Settings → Tools and costs no credits.

Recording a take

🎙 Record in the line panel records a take with your microphone. The microphone and its level meter start when the recorder opens, so the static some microphones make when switched on has passed before you press Record. After recording, drag Start and End to trim, and Play selection to hear it.

  • Keep my recording saves it as a new take: trimmed, levelled, faded out and given a .lip from the spoken text.

  • Convert to <voice> and keep first sends it through ElevenLabs speech-to-speech into the patch's voice, so your timing and delivery carry over. It uses the Voice Changer settings and is billed by audio length. The button explains itself when it can't be used, for example without an ElevenLabs voice.

If the meter stays flat, check that Windows lets apps use the microphone (Settings → Privacy & security → Microphone).

Importing an earlier pack

More ▾ → Import an earlier voice pack… brings in a voice pack you made before, with this tool or another. Pick its folder; .fuz files and WAV + LIP pairs are found at any depth and matched to lines by Legacy or DBVO 2.0 names. The preview counts what matches before anything is imported.

Only lines without a take are filled, so nothing you made here is replaced. An imported .fuz becomes a take marked Imported .fuz, kept as it is, and its .fuz is reused when you build. A backup is made first.

Merging takes

More ▾ → Merge takes from another patch… copies takes from another patch of the same voice pack, for lines both share. It suits a patch split in two, or work started twice. Takes are added, never replaced, and the dialog shows how many lines match and how many exist only in the other patch. A backup is made first.

Editing in a spreadsheet

More ▾ → Spoken text to a spreadsheet (CSV)… writes Line ID, File name, Original line and Spoken text for every line, using your Windows list separator so Excel opens it in columns. Edit the Spoken text column and save as CSV.

Spoken text from a spreadsheet (CSV)… reads it back (comma, semicolon or tab) and lists each change, old and new; untick any you don't want, then apply. Lines are matched by Line ID; other columns are ignored.

Phase 3: FOMOD Creation

Phase 3 builds the installer: pages of options that install each mod's .fuz files and DBVO Fix plugins, plus the DBVO voice pack JSON that makes the voice selectable in DBVO's MCM. A FOMOD project belongs to one voice pack.

1. Start a project

+ New FOMOD asks for the voice pack, a name and the FOMOD root folder: the folder that holds your patch folders and images, pre-filled from the voice pack's final folder. File sources in the installer are relative to it. A new project already has a Core page with one Required option that carries the DBVO JSON.

To keep working on an installer made elsewhere, Import FOMOD… reads any ModuleConfig.xml, such as one from FOMOD Creation Tool. Pages, groups, options, descriptions, images, files, detection, flags, conditions and visibility are all kept. Re-import… replaces the open project the same way.

2. Add your patches

+ Add DBVO Patches… lists this voice pack's patches, with or without the Voice Changer on. Each mod becomes an option on the page of its category, made if missing. The option detects the mod's plugins and installs its Sound folder and DBVO Fix plugins from the patch's final folder.

These options are linked (🔗). ⟳ Refresh linked updates their files after you change folders or rebuild .fuz files, and every build does it too. Unlink stops updates for one option; if its patch is deleted, it is left as it was and reported.

3. Edit pages, groups and options

The tree on the left holds ⚙ Installer & info.xml, { } DBVO voice pack JSON, then the pages, groups and options. Drag options between groups to reorder them; + Page adds a page. Everything saves as you type.

4. The DBVO JSON

Turn on Add to the installer, set voice_pack_name (shown in DBVO's menu) and voice_pack_id (must match the folder under Sound\DBVO\), and tick Carries the DBVO JSON on one Required option. The file holds only those two fields, and its install path follows the voice pack's naming.

5. Check it

Validate checks the ModuleConfig 5.0 schema, missing files and images, the JSON carrier, empty pages, duplicate names, and groups that could block the user. Click an issue to jump to its option.

Simulate install shows what Mod Organizer 2 or Vortex would pre-tick for a list of active plugins (type them or Load plugins.txt…). Tick options to try choices; it lists the files that would install, missing ones in red, and files installed by more than one option.

View XML shows the generated ModuleConfig.xml, info.xml and DBVO JSON.

6. Build

Build ▾ offers Build and pack (.zip or .7z) or Stage only, which builds the installer folder without an archive so you can test it in MO2 or Vortex. A build refreshes linked options and validates first; any error stops it with Fix these first. It then makes a backup, stages everything in <release folder>\_staging\<name version> and packs the archive, named from the mod name and version.

Pack as BSA

The installer's Voice files setting is Loose files or Pack as BSA. With BSA, each option's Sound folder is packed into one .bsa named after the option's DBVO Fix plugin, so the game loads it with that plugin; an option without one gets a small empty ESL-flagged plugin to load it. Fewer loose files means a cleaner Data folder and faster installs. An option over about 2 GB stays as loose files, with a warning in the build report.

Other Tools

Both tools open from Other Tools ▾, and the open tool's name shows in the top bar after the three phases. Neither needs Phase 1 or a voice pack.

NPC Revoice Tool

NPC Revoice replaces the voice files of NPC dialogue in any mod or the base game, line by line, with voices from your ElevenLabs account or local servers. Exports go to the exact paths the game plays, so no plugin is needed unless you give an NPC a voice type of their own. Set the base game folder in Global Settings first: masters, vanilla voices and strings are read from there.

Create a project with + New revoice. It has four tabs: Setup, Speakers, Lines and New voice types.

Setup

Drop the mod's plugins, its .bsa, .zip or .7z archives, or folders (a Data folder, an MO2 mod folder or an unpacked download). A plugin brings its own archives and its Sound\Voice folder along. Then click Scan.

  • Revoice its lines marks which plugins are revoiced; the rest are only read for masters, NPCs and conditions. The base game is listed but off, since it holds many thousands of lines.

  • Voice file sources are where the current voice files are. Higher priority wins, and loose files beat archives, as in game.

  • Output folder is where exports go; use an empty folder or a new MO2 mod folder.

  • Emotion tags suggests a tag from each line's emotion (Anger 80 → [angry]) for you to accept or undo.

  • ⟳ Rescan after the mod changes; your takes and edits are kept.

After a scan, banners can offer to Match orphaned files… (voice files whose FormIDs changed when a plugin was merged, compacted or renamed, matched by name and then by Whisper), ask whether lines that got another speaker should move to it, report lines changed in the mod since their take, or list missing masters and strings.

Speakers

A speaker is one NPC when a line belongs to one character, or a voice type when several NPCs share the line. Two NPCs with the same vanilla voice type can still get different voices for their own lines; only the lines they share must share a voice.

Pick an engine and a voice for each speaker, or Skip one. The table shows lines, done and characters (about ElevenLabs credits). The engine settings above it are shared by every speaker, and Lines → jumps to that speaker's lines.

Lines

The toolbar and tag bar work as in Phase 2. Pick a speaker in the toolbar to filter the list and change that speaker's voice right there.

  • Speaker marks a probable or unknown speaker with ?; the Speaker unsure filter collects these.

  • Now plays the file the game uses today; — means the line is silent in game.

  • Subtitle never changes. Spoken text is what the new voice says, with tags allowed.

  • Ticked (N) ▾ accepts or undoes suggested tags, excludes, includes, flags, or keeps only the used take.

  • Generate ticked, Flagged and Generate missing make takes. With a speaker picked in the toolbar they make only that speaker's lines, as their counts show. Lines whose speaker has no voice are skipped. Before a batch, Check before spending credits names the speaker and shows every setting each voice will use; while it runs, Generate missing becomes ■ Stop generating.

New voice types (optional)

Use this only for one NPC who shares a vanilla voice type and should sound different in all their lines, including greetings and combat. For example, Aela shares FemaleCommander with Uthgerd, Rayya and Legate Rikke.

+ Give an NPC a new voice type… (after a scan) writes an ESL plugin with only the voice type record, a SkyPatcher file that gives it to the NPC, and a FormList Manipulator file that adds it to the lists that unlock dialogue. Nothing is overridden. Edit & coverage… sets the EditorID, the NPC copies, extra NPC records, the form lists, and which lines to generate, and shows which responses would go silent. Rescan after saving.

Voice Changer and export

The project's Voice Changer converts the game's current recordings into the new voice instead of using text-to-speech, so delivery and timing come from the original performance.

Export ▾ writes <output folder>\Sound\Voice\<plugin>\<voice type>\<file>.fuz, replacing files already there or keeping them, plus any new voice type files. If an earlier export left files no line uses any more, you choose to delete or keep them; only files this tool wrote are listed.

WAV to LIP Tool

WAV to LIP makes .lip files from audio alone. Whisper listens to each WAV and writes its transcript, then FaceFXWrapper makes the .lip next to it. Other LIP tools need the text of every file typed in; this one doesn't.

  1. Lip-generation tools must show ✓ for FaceFXWrapper.exe and FonixData.cdf; Change in Global Settings goes to the paths.

  2. Whisper transcription: Built in needs nothing else; My faster-whisper uses your own Python setup. Pick the model (large-v3 is about 3 GB and downloads on first use), language and device, and keep retry on CPU on.

  3. Drop WAV files or folders, or use Add WAV files… / Add folder…. Files that already have a .lip show has .lip. Remove selected and Clear change only the list, never the disk.

  4. Click Transcribe + Generate .LIP. You are asked before existing .lip files are overwritten; progress and a log show on the right.

Why is this button greyed out?

Almost every blocked action has one of three causes: a job is running, the line is left out (excluded, omitted, gone or skipped), or something it needs is missing (a voice, a folder, a tool). Hover the greyed-out button: its tooltip names the reason.

One job at a time

The app runs one background job at a time: generation, .fuz building, Import from .fuz, a FOMOD build, WAV to LIP, or an NPC Revoice scan, export or Whisper match. The running job shows in the top bar with Cancel.

While a job runsYou see
Generate and Convert buttons, the row ↻, Export ▾, Takes ▾, Build ▾, Scan, Transcribe + Generate .LIP, Import from .fuzGreyed out; A job is running (see the top bar)
Switching a patch's voice pack, turning the Voice Changer on or offWait for the running job, or cancel it.

If the app crashed mid-job, the indicator clears itself the next time a page loads, so buttons never stay stuck.

Files, backups and troubleshooting

Your work lives in the Library; your exports live in folders you choose. The app deletes exported files only after asking, and never touches another tool's files unless Overwrite is on.

Backups

A backup zips every project and settings file in the Library, named with the date, time and reason. It does not contain audio.

  • Automatic before importing mods, deleting a mod, plugin, patch, FOMOD or revoice project, generating, and building a FOMOD. Generation and build backups are marked -auto-, made at most every 10 minutes, and rotated separately.

  • Backups to keep sets how many of each kind stay; Back up now makes one on demand.

  • To restore, close the app and unzip the backup over the Library folder. Deleting a patch or revoice project deletes its takes, so a restore brings the project back without its audio.

  • To move the Library, use Change… rather than moving the folder by hand, and keep the old folder until you have checked the new one.

Problem messages

When something goes wrong, a red message at the bottom says what happened in plain words and what to do. It stays longer than other messages; ✕ closes it. When the fix is a setting, Open Global Settings goes straight to that section.
